# UltBot Manager

Веб-панель для управления множеством mineflayer-ботов (аккаунтов) одновременно:
подключение/отключение, HUD (HP/еда/координаты/пинг), клавиатурное управление,
поворот камеры, хотбар и полный инвентарь, окна (сундук/печь/верстак), чат,
пул прокси с ручным и авто-выбором, авто-реконнект, кликер, авто-бал, авто-хил,
авто-payday, авто-отправка команд по таймеру, слежение за координатами и гибкие
макросы (разовые и бесконечные). Плюс отдельный Telegram-мост (`Tgbridge.py`).

## Установка и запуск

```bash
npm install
node server.js
```

Панель поднимется на `http://localhost:3000` (или на порту из переменной
окружения `PORT`). Все аккаунты хранятся в `accounts.json`, прокси — в
`proxies.json`, настройки сайта — в `settings.json`. Эти три файла создаются
автоматически при первом запуске/сохранении и не удаляются между рестартами
`npm start` — всё состояние (кликер, авто-бал, авто-хил, авто-payday,
авто-реконнект, авто-отправка команд, бесконечный макрос, запомненные
координаты) переживает перезапуск процесса.

## Вкладка «🛠️ Настройки»

Здесь собраны значения, которые иначе пришлось бы редактировать в коде.
Меняются на лету, без перезапуска сервера:

| Раздел | Что настраивается |
|---|---|
| Сервер по умолчанию | хост/порт/версия, которые подставляются в новую плашку бота и в панель массового подключения |
| Авто-бал | команда проверки баланса, команда инвеста (с `{amount}` — подставляется найденная сумма), интервал |
| Авто-хил | команда лечения, интервал |
| Авто-payday | команда получения выплаты, команда перевода (с `{target}`/`{amount}`), получатель, сумма, интервал в часах |
| Слежение за координатами | порог отклонения в блоках, через сколько секунд повторять макрос восстановления |
| Пул прокси | лимит ботов на один прокси (по умолчанию 3) |
| Авто-логин/регистрация | шаблоны команд `/register`/`/login` по умолчанию и regex-паттерны, по которым бот распознаёт, что сервер просит зарегистрироваться или войти |

Кнопка «↺ Сбросить по умолчанию» возвращает все значения к заводским.

## Прокси

### Пул прокси (вкладка «🌐 Прокси»)
Добавляются списком, по одному на строку:
```
ip:port
ip:port:user:pass
socks5://user:pass@ip:port
```
При подключении бота, у которого не назначен свой прокси, сервер сам берёт
наименее загруженный прокси из пула (лимит — см. настройки). Кнопка
«🔍 Проверить» у каждой строки прогоняет реальное SOCKS/HTTP-рукопожатие
через прокси, а не просто проверяет, что порт открыт.

### Быстрый выбор прокси для конкретного бота — кнопка 🪄
В шапке каждой плашки бота, рядом с ✏ (редактировать) и ✕ (удалить), есть
кнопка 🪄. По клику выпадает список всех прокси из пула с индикацией
занятости (`N/лимит`, красным — если прокси уже заполнен). Выбор строки:
- назначает этот прокси боту (сохраняется в `accounts.json`, переживает рестарт);
- сразу же (пере)подключает бота через него, используя хост/порт/версию,
  указанные в полях плашки.

Пункт «🎲 Авто (из пула)» сбрасывает ручной выбор — при следующем
подключении сервер снова сам подберёт наименее загруженный прокси.

## Макросы

Есть два независимых способа задать последовательность действий:

1. **Макрос восстановления** (в модалке редактирования бота) — запускается
   автоматически по триггерам «переподключение» / «смерть или смена мира»,
   а также при слежении за координатами (см. ниже).
2. **Панель «📜 Макрос»** на самой плашке бота — тот же язык команд, но
   запускается вручную, в двух режимах:
    - **▶ Разовый запуск** — проходит все шаги один раз и останавливается;
    - **🔁 Бесконечный (по кругу)** — проходит все шаги, ждёт указанную паузу
      и повторяет заново; кнопка превращается в «■ Остановить цикл». Это
      состояние тоже сохраняется и переживает рестарт сервера — если бот
      был онлайн и цикл был активен, после реконнекта он запустится заново.

Текст макроса можно вставить вручную, вставить из `.txt` файла кнопкой
«📂 Файл», а строки начинающиеся с `#` — комментарии, игнорируются.

### Список команд макроса

| Команда | Пример | Что делает |
|---|---|---|
| `chat:` | `chat:/hub` | Написать сообщение/команду в чат |
| `wait:` | `wait:2000` | Подождать N миллисекунд |
| `walk:` | `walk:forward:1500` | Идти в направлении (`forward`/`back`/`left`/`right`) N миллисекунд, затем остановиться |
| `look:` | `look:90:0` | Повернуться на `yaw:pitch` в **градусах**, абсолютно |
| `jump` | `jump` | Один прыжок |
| `sneak:` | `sneak:1000` | Присесть (шифт) на N миллисекунд |
| `sprint:` | `sprint:2000` | Бежать (спринт) N миллисекунд |
| `attack` | `attack` | Разовый удар (ЛКМ) |
| `use` | `use` | Разовое использование предмета в руке (короткий ПКМ) |
| `hold:` | `hold:left:3000` | Зажать ЛКМ на N мс (частые повторные удары, как ручной клик) |
| `hold:` | `hold:right:3000` | Зажать ПКМ на N мс (использовать и держать предмет — удочка, лук, еда, щит и т.п.) |
| `slot:` | `slot:3` | Выбрать слот хотбара, 0–8 |
| `click:` | `click:12:0:0` | Клик по слоту инвентаря/открытого окна: `слот:кнопка[0=ЛКМ,1=ПКМ]:режим[0=обычный,1=shift]` |
| `clicker:on:` | `clicker:on:0:600` | Включить автокликер: `кнопка[0/1]:задержка_мс` |
| `clicker:off` | `clicker:off` | Выключить автокликер |

Пример полного макроса (телепорт домой удочкой из слота 1, забросить и
подождать):
```
# возврат на точку и заброс удочки
chat:/hub
wait:2000
slot:0
hold:right:1200
wait:500
click:12:0:0
```

## Слежение за координатами

Кнопка «📍 Запомнить» на плашке бота сохраняет текущие X/Y/Z. Если бота
унесло дальше порога из настроек (по умолчанию 15 блоков — кик, телепорт,
смерть и т.п.), автоматически запускается макрос восстановления. Если бот
за настроенное время (по умолчанию 30 сек) так и не вернулся к точке —
макрос повторяется снова. Кнопка «✕ Забыть» выключает слежение.

## Авто-функции на плашке бота

- **Кликер** — авто-клик ЛКМ/ПКМ с заданной задержкой.
- **Авто-бал** — периодически шлёт команду проверки баланса, парсит сумму
  из ответа и переводит её командой инвеста.
- **Авто-хил** — периодически шлёт команду лечения.
- **Авто-payday** — раз в N часов получает выплату и переводит фиксированную
  сумму указанному получателю.
- **Авто-реконнект** — если соединение оборвалось (кик, краш сервера,
  сетевая ошибка), бот сам переподключается с нарастающей паузой.
- **Авто-отправка команды** (панель «Управление» → массовые действия) —
  шлёт заданный текст выбранным ботам по таймеру.

Все эти состояния (включено/выключено, интервалы, тексты) сохраняются в
`accounts.json` и восстанавливаются как при обычном реконнекте, так и после
полного перезапуска `npm start`.

## REST API

Полный список — в `server.js`. Основные группы:

- `GET/POST/DELETE /api/proxies`, `GET /api/proxies/usage`, `POST /api/proxy-test` — пул прокси
- `GET/POST /api/settings`, `POST /api/settings/reset` — настройки сайта
- `GET/POST /api/bots`, `PUT/DELETE /api/bots/:id` — CRUD аккаунтов
- `POST /api/bots/:id/connect|disconnect`, `POST /api/bots/all/connect|disconnect|chat` — подключение
- `POST /api/bots/:id/proxy` — ручной выбор прокси (`{ proxy, reconnect }`)
- `POST /api/bots/:id/jump|attack|use|chat` — разовые действия (используются, например, из `Tgbridge.py`)
- `POST /api/bots/:id/autoBal|autoHeal|autoPayday` — авто-функции

Веб-интерфейс общается с сервером в основном через Socket.IO
(`bot:chat`, `bot:key`, `bot:look`, `bot:clicker`, `bot:runMacro`,
`bot:macroLoop`, `bots:bulkAction` и т.д.) — см. `io.on('connection', ...)`
в `server.js`.

## Telegram-мост (опционально)

```bash
pip install pyTelegramBotAPI "requests[socks]"
python Tgbridge.py
```

Настройки берутся из `.env` в корне проекта:

```
TG_TOKEN=токен_бота_от_BotFather
TG_ALLOWED_IDS=123456789,987654321   # необязательно; пусто = доступ всем
NODE_API_URL=http://localhost:3000
TG_PROXY=                             # необязательно, host:port[:user:pass]
```

Мост общается с уже запущенным `server.js` через его REST API — Node и
Python-процесс запускаются независимо, в двух консолях.

## Структура

- `server.js` — Express + Socket.IO сервер, REST API, хранение аккаунтов/прокси/настроек
- `botmanager.js` — обёртка над mineflayer: подключение, HUD, инвентарь, окна,
  макросы, авто-функции, авто-реконнект, слежение за координатами
- `settings.js` — модуль настроек сайта (`settings.json`)
- `interact.js` — низкоуровневые действия взаимодействия с миром (атака, использование предмета)
- `proxyconnect.js` — SOCKS4/5 и HTTP CONNECT туннели для подключения ботов через прокси
- `public/` — фронтенд (без сборки, чистый HTML/CSS/JS)
- `Tgbridge.py` — Telegram-бот для управления через REST API
